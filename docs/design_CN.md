# 日历程序设计文档

[English](design.md) | 中文

LookForwardCalendar（LFCalendar），基于 FTXUI 的终端日历：月视图 + 日程管理（瞬间型事件 / 固定日程 / 长期任务）+ 农历 + 中日节假日。

## 1. 技术栈

| 项目 | 选择 |
|---|---|
| 语言 | C++23（日期计算用 `<chrono>`） |
| UI | FTXUI v7.0.3 |
| JSON | nlohmann/json（header-only，FetchContent 引入） |
| 构建 | CMake + Ninja，GCC 15.1（MinGW），静态链接 |
| 平台 | 仅 Windows，不考虑跨平台 |

## 2. 数据目录

根目录为 **exe 所在目录**下的 `data/`（不依赖启动时的工作目录）。

```
data/
  general/<年>/<月>.json        当月每天的属性及瞬间型事件，例：general/2026/11.json
  task/<创建日期>_<短id>.json   每个长期任务一个文件（操作日志），例：task/20261102_a3f9.json
  fixed/<创建日期>_<短id>.json  每个固定日程一个文件，例：fixed/20261103_b71c.json
  preference.json               配置：{ "holiday_config": 1, "language": "EN", "lunar": true, "slogan": "Look Forward!" }
  holidays/config<配置>_<年>.json  节假日配置的节假日，例：holidays/config1_2027.json
```

语言文件不属于用户数据，放在 exe 所在目录下的 `language/`（`EN.json`、`CN.json` …），由 CMake 在编译后从源码的 `language/` 复制过去。

## 3. 数据模型

### 3.1 Day（每天一个对象）

`general/2026/11.json`：以日期为键，没有内容的日期不写入。

```json
{
  "2026-11-02": {
    "events": [
      { "title": "组会", "start": "14:00", "end": "15:30", "note": "" }
    ]
  }
}
```

- 瞬间型事件直接保存在 Day 上。
- 事件的增删改都是直接改写当月文件。

### 3.2 FixedSchedule（固定日程，一个固定日程一个文件）

```json
{
  "id": "b71c",
  "title": "组会",
  "start": "09:00",
  "end": "10:00",
  "note": "会议室 A",
  "repeat": "weekly",
  "weekdays": [2, 4],
  "from": "2026-11-03",
  "until": ""
}
```

- `repeat`：`daily` / `weekly`（默认）/ `biweekly` / `monthly`。`weekdays`（1=周一…7=周日）只用于 weekly、biweekly。
- biweekly 以 `from` 所在的那一周为第一周；monthly 在 `from` 的日期重复，没有这一天的月份跳过。`until` 为空表示一直重复（含 `until` 当天）。
- 启动和刷新时读入全部定义；某个月第一次显示时才展开为该月每天的列表并缓存（`AppState::FixedOn`），增删后清空缓存。
- 只能新建和删除；删除即删除文件，所有日期一起消失。

### 3.3 Task（长期任务，一个任务一个文件）

文件里保存的是**操作日志**，任务的当前状态和每天的工作量都由重放日志计算得到。

```json
{
  "id": "a3f9",
  "name": "毕业论文",
  "log": [
    { "at": "2026-11-02T22:10", "op": "create",
      "hours_total": "40:00", "due": "2026-12-20",
      "weekdays": [1, 2, 3, 4, 5], "skip_holiday": true, "holiday_config": 1 },
    { "at": "2026-11-03T21:00", "op": "progress", "date": "2026-11-03", "minutes": 150 },
    { "at": "2026-11-10T09:00", "op": "modify", "fields": { "due": "2027-01-10" } },
    { "at": "2026-11-15T20:00", "op": "pause" },
    { "at": "2026-11-18T20:00", "op": "resume" },
    { "at": "2026-12-01T18:00", "op": "complete" }
  ]
}
```

| op | 含义 | 字段 |
|---|---|---|
| `create` | 创建 | 预定总时长、截止日期、每周工作日（1=周一…7=周日）、是否跳过节假日、节假日配置（`holiday_config`，1 / 2；v1.5.0 之前的日志为 `country`：CN → 1，JP → 2） |
| `progress` | 录入某天实际工作量 | `date`、`minutes`、`note`（同一天再次录入时覆盖） |
| `modify` | 修改属性 | `fields`：总时长 / 截止日期 / 工作日 / 名称等 |
| `pause` / `resume` | 暂停 / 恢复 | 暂停后截止日期不变 |
| `complete` | 提前（或按期）完成 | |
| `abort` | 中止 | |

- 短 id：创建时随机生成 4 位十六进制，作为属性保存；如果和已有任务或固定日程重复就重新生成。
- 文件名：`<创建日期>_<短id>.json`，任务名只保存在文件内容里。

### 3.4 任务状态机

```
           pause            complete / abort
 进行中 ─────────▶ 暂停 ─────────────────▶ 已结束
   ▲ ◀─────────── │
   │    resume    │
   └─ 超期未完成 ─┘（自动进入暂停，标红）
```

### 3.5 每日工作量计算

对某个任务和日期 D（今天及以后）：

```
R = 总时长 − 实际录入工时之和（今天之前的）
N = 今天 到 截止日期 之间的工作日数（包括今天）
工作日 = 星期属于 weekdays，且（skip_holiday 为假，或该日不是节假日配置 holiday_config 的放假日）
每天分配量 = ceil(R / N)，向上取整到 10 分钟
```

- 创建当天算一天。
- 按顺序逐日分配：每天取 ceil(剩余 / 剩余工作日数)，向上取整到 10 分钟，再从剩余中扣除。所以越往后的日子分到的量可能略少，总和正好等于剩余量。
- 今天的计划只用**今天之前**录入的工作量计算，今天录入的工作量不改变今天的目标。
- 没有录入的日子按 0 分钟计，后续几天的量会自动增加。
- 暂停期间不分配工作量，截止日期不变，恢复后每天的量相应增加。
- 已完成、已中止的任务不再分配。
- 超期（或已经没有可用工作日）但 R > 0：任务标红，作为**计算出的暂停状态**（不写日志）；延长截止日期后自动恢复。
- 不考虑补班日（节假日数据里的 `off: false` 只用于显示）。
- **实际工作量录入**：侧边栏任务的 [进行] 按钮，结果为覆盖写入，可以随时修改；今天及以前的日期都可以录入（含补录）。
- **过去的日期**：月历格子显示当天实际录入的工时。
- **刷新（r）**：重新读取磁盘上的全部文件，更新“今天”，重算所有安排。每次修改后也会自动重算。

## 4. 农历

- 内置 1900–2100 年的农历压缩数据表（每年一个整数，编码闰月和大小月），不联网。
- 能算出：农历日期、干支、生肖、农历节日（春节、元宵、端午、七夕、中秋、重阳、除夕）、二十四节气（含清明、冬至）。

## 5. 节假日

### 5.1 节假日配置与文件格式 `holidays/config<配置>_<年>.json`

```json
{
  "country": "中国",
  "year": 2027,
  "days": [
    { "date": "2027-02-06", "name": "春节", "off": true },
    { "date": "2027-02-14", "name": "春节调休补班", "off": false }
  ]
}
```

- `off: true` 表示放假日；`off: false` 表示补班日（如中国）。
- 节假日配置共两个（`kHolidayConfigCount`），是不与国家绑定的固定槽位；配置和年份由文件名决定，不写在内容里。
- `country` 只是配置的一个属性：生成提示词时填写的国家名称，只用于提示词和侧边栏“国家：假日”的显示。
- v1.5.0 之前的文件（`CN_<年>.json`、`JP_<年>.json`）在读取时自动改名为 `config1_…` / `config2_…`，`country` 的 CN / JP 改为 中国 / 日本。
- 只列出特殊日期，没列出的日期按普通工作日或周末处理。

### 5.2 导入流程

1. 在程序里按快捷键，选择节假日配置（1 / 2），填写国家和年份，弹窗显示提示词，并自动复制到剪贴板。
2. 用户把提示词发给任意 AI，把返回的 JSON 保存成文件。
3. 在程序里输入文件路径，程序校验格式（字段、日期是否合法、年份是否一致）。
4. 校验通过后写入 `holidays/config<配置>_<年>.json`，同一配置同一年的旧数据整体覆盖。

### 5.3 提示词模板（程序内置，`{COUNTRY}` / `{CONFIG}` / `{YEAR}` 会被替换）

提示词本身也是一条界面文字：源码中为英文，下面是 `CN.json` 中的中文译文，界面语言为 CN 时使用。

```
请列出{COUNTRY}{YEAR}年全年的法定节假日安排，严格按照下面的 JSON 格式，
把完整的 JSON 放在一个 ```json 代码块中输出，代码块外不要输出其他文字。
如果你能够生成文件，请同时生成一个名为 config{CONFIG}_{YEAR}.json 的文件供下载，内容与代码块中的 JSON 完全相同。

{
  "country": "{COUNTRY}",
  "year": {YEAR},
  "days": [
    { "date": "YYYY-MM-DD", "name": "节日名称", "off": true }
  ]
}

规则：
1. 每个日期单独一条，连续放假的每一天都要列出。
2. 放假日（含周末因节日顺延的补休/振替休日）"off" 为 true。
3. 因调休需要上班的周末（补班日）也要列出，"off" 为 false，name 写“XX调休补班”。
4. name 使用该国语言的通用名称。
5. 只列出 {YEAR} 年内的日期，按日期升序排列。
6. 依据该国政府官方公布的安排；如果官方尚未公布，请在 name 后加“(预测)”。
```

## 6. 界面（月视图）

```
┌ 2026 年 11 月 ──────────────────────────────────┬ 11月2日 周一 ──────────┐
│  日     一     二     三     四     五     六   │ 农历 十月初二          │
│ ┌────┐                                          │                        │
│ │ 2  │  公历日 / 农历或节日、节气                │ 【事件】               │
│ │初二│                                          │  14:00-15:30 组会      │
│ │●2  │  瞬间型事件数                            │                        │
│ │▶3h │  当天任务总工时（超期任务标红）           │ 【任务】               │
│ └────┘                                          │  毕业论文  计划 2:00   │
│                                                 │            实际 1:30   │
│                                                 │  [进行][暂停][修改]    │
├─────────────────────────────────────────────────┴────────────────────────┤
│ 快捷键提示：移动 / 功能 / 配置                                           │
└──────────────────────────────────────────────────────────────────────────┘
```

- 每周从周日开始（日 一 … 六）；对话框中的星期复选框、“每周日一三”等文字也按这个顺序。数据中的星期仍以周一为 1。
- 放假日和补班日用不同颜色标出。
- 侧边面板：当天的事件和固定日程；各任务当天的计划量、实际工作量和按钮。

## 7. 模块划分（实际结构）

```
src/
  core/        不依赖 UI
    date.*         日期与时长工具（std::chrono）
    lunar.*        农历、节气、农历节日、干支生肖
    holiday.*      节假日格式校验、提示词、HolidayCalendar
    i18n.*         多语言：Tr() / N_()、语言文件解析
    json.h         nlohmann::ordered_json 别名
  model/
    day.*          Day / Event 及 JSON 转换
    task.*         Task 日志、重放、工作量计算、校验
    fixed.*        FixedSchedule 重复规则、JSON 转换、校验
    preference.*   配置（节假日配置、语言、农历开关、标语）
  store/
    fs_util.*      UTF-8 路径、原子写文件
    repository.*   读写 general/ task/ fixed/ holidays/ preference.json
  app/
    app_state.*    应用状态：所有修改经由这里（写盘 + 重算 + version 递增）
  platform/
    platform.*     exe 目录、剪贴板、控制台 UTF-8（Windows API）
  ui/            FTXUI
    widgets.*      公共样式与小部件（按钮、输入框、面板、中文自动换行 WrapText）
    logo.*         像素风 logo（关于窗口）
    month_view.*   月历网格
    day_panel.*    侧边栏（选中日期的事件、固定日程与任务）
    overview_screen.* / reminder_screen.*  整屏的任务总览与提醒列表
    dialogs.*      对话框基类 + 事件 / 固定日程 / 任务 / 进行 / 节假日导入 / 关于
    app.*          组装、全局快捷键、快照渲染
  main.cpp
tests/test_main.cpp  core / model 单元测试
res/                 exe 图标（app.rc + LookForward.ico）
tools/make_icon.py   由 logo.cpp 的像素数据生成 res/LookForward.ico 和 docs/logo.png
tools/i18n.py        扫描源码中的界面文字，生成 language/EN.json，检查其他语言文件
language/            语言文件（EN.json 为模板，CN.json 为中文）
```

- `calendar_core` 静态库包含 UI 以外的全部代码；`LookForward`（程序本体）与 `calendar_tests` 都链接它。
- UI 的扩展点：新面板实现为 `ComponentBase` 子类；新对话框继承 `Dialog`（自带 Esc 关闭、Tab 焦点顺序、错误行）；动态控件按 `AppState::version()` 惰性重建。
- 开发调试：`LookForward --data <目录> --snapshot 150x40 "n,TAB,10"` 依次送入按键后，把界面渲染为文本输出。
- 发布：`./build.sh package` 用 `release` 预设编译（`build-release/`，链接时加 `-s`），运行单元测试，把 `LookForward.exe`、`language/`、README 和 `docs/logo.png` 打包为 `dist/LookForward-v<版本>-win64.zip`（版本号读自 `src/version.h`）。`data/` 不打包，首次使用时在 exe 旁边自动生成。

## 8. 已确定的决定

1. 不考虑补班日。
2. 今天的计划只按今天之前的实际工作量计算。
3. 实际工作量为覆盖写入，可以随时修改，允许补录过去的日期。
4. 超期只作为计算出的暂停状态，延长截止日期后自动恢复。
5. （v1.5.0 修改）跳过节假日的任务可以跨入还没有节假日数据的年份，这些年份按没有节假日计算。导入节假日和刷新（`r`）时会重新读取节假日并重算所有安排，数据补上后安排自动修正。（v1.5.0 之前会拒绝创建或修改这样的任务。）
6. （已被第 10 条取代）右侧单独一栏（固定宽度）显示所有任务的总览和进度条；月历格子随窗口宽度缩放。
7. 快捷键只用小键盘上也有的键：方向键或 `h j k l` 移动，`[ ]` 翻月，`t` 回到今天，`Tab`/`Esc` 切换面板；`a` 事件、`n` 任务、`i` 导入节假日、`c` 切换节假日配置、`r` 刷新、`q` 退出。
8. 任务行的 [进行] 按钮打开对话框，填写当天的实际时长和进行内容（日志 progress 条目的 `note` 字段），覆盖写入，可以反复修改；未来日期锁定，不能填写。
9. **事件提醒**：新建/编辑事件时可勾选“提醒”并填写提前量（`30m` / `1:30` / `2`（小时）/ `1d`，最长 30 天），保存在事件的 `remind` 字段（分钟）。
   提醒期间为 [开始时间 − 提前量, 结束时间)；无结束时间则到开始那一分钟结束；全天事件以 0:00 为开始、到当天结束。
   处于提醒期间的事件进入提醒列表，按发生时间排序；主界面状态栏显示提醒条数。程序每 30 秒自动刷新一次，跨零点时自动重载。
10. **子界面**：右侧总览栏取消，改为整屏子界面。`o` 任务总览（`1` 进行中按截止日期排序、`2` 全部按创建日期排序、`3` 已完成按最终截止日期排序），`m` 提醒列表（Enter 跳到该日期）。`Esc`/`q` 返回主界面。
11. 界面上显示任务的地方都附带 `(ID:xxxx)`。`v` 打开版本信息；版本号写在 `src/version.h`（当前 v1.5.0，2026-11-03；关于窗口显示像素 logo 和编写模型 Claude Opus 5.5），CMake 的 `project(VERSION)` 与之保持一致。
12. 任务总览中 `Enter` 查看选中任务的全部日志（按时间顺序，由 `DescribeLogEntry` 生成可读文字），`d` 删除任务文件（按 `y` 确认）。子界面自行处理返回键。
13. **v1.2.0**：程序命名为 LookForwardCalendar（简称 LFCalendar，可执行文件 `LookForward.exe`）。
    节假日提示词要求 AI 把 JSON 放在 ```json 代码块中，能生成文件时同时生成数据文件；导入时忽略代码块前后的说明文字。
    侧边栏、状态栏消息、对话框提示改用 `WrapText` 自动换行（`ftxui::paragraph` 只在空格处断行，长中文不换行）；侧边栏只做纵向滚动（`yframe`）。
    侧边栏任务的显示顺序：任务名 / ID 与状态 / 计划与实际 / 进行内容 / 按钮行（进行、暂停或恢复、修改、中止、完成），任务之间空一行。
    像素 logo 同时作为 exe 图标：`logo.cpp` 是唯一的像素数据来源，`tools/make_icon.py` 从中生成图标（生成结果提交到仓库，编译时不需要 Python）。
14. **v1.3.0 固定日程**：`f` 新建（开始日期默认选中日期，重复默认每周、星期默认开始日期的星期）。
    月历格子第三行用青色 `◆n` 显示固定日程数；侧边栏在事件和任务之间显示【固定日程】，每项为时间段、工作内容、重复方式、备注和 [删]。
    [删] 删除整个固定日程，需按两次（第一次变为 [确认删除] 并在状态栏提示），侧边栏重建（切换日期或数据变化）时取消待确认状态。
    固定日程的 id 与任务 id 共用生成器，互不重复。暂不支持修改、跳过节假日和提醒。
15. **配置**：`data/preference.json` 保存月历显示的节假日配置、语言和农历开关，启动和刷新（`r`）时读取，`c` 切换节假日配置、`g` 切换语言后立即写回。
    文件不存在时使用默认值（节假日配置1、英文、显示农历）；不合法的值回退为默认值并在状态栏提示。v1.5.0 之前的 `country` 按配置读取（CN → 1，JP → 2）。
    状态栏快捷键提示分为三行：“移动”、“功能”、“配置”（`c` 节假日配置、`i` 导入节假日、`g` 语言、`u` 农历开关、`e` 标语）。
    节假日配置是固定槽位而不是国家（见 5.1）：界面上一律称为“节假日配置1 / 2”（月历标题、状态栏、导入节假日和长期任务对话框、任务总览、任务日志描述、错误提示；`HolidayConfigName` / `HolidayConfigShortName`）。任务和 `preference.json` 保存配置编号；国家只出现在提示词和侧边栏“国家：假日”中。导入对话框有国家输入框，默认填入该配置最近一年数据的国家（`HolidayCalendar::LatestCountry`）。
16. **v1.4.0 多语言**：程序中的固定文字都经过 `Tr()`，以英文原文作为 key；`language/<名称>.json` 是 `{ key: 译文 }` 的平面对象。
    - 默认语言 EN；`EN.json` 的 key 与 value 相同，作为翻译模板，由 `tools/i18n.py` 从源码生成（扫描 `Tr("…")` 和 `N_("…")`）。自带 `CN.json`。
    - 可变部分用命名占位符 `{name}`，译文可以调整语序；找不到的 key 显示英文原文。
    - 特殊 key `" "` 是词间分隔符（星期简称、时长），中文为空字符串；key `"English"` 的译文是该语言自己的名称。
    - 常量表里的文字（星期、月份、标签页）用 `N_()` 标记，使用处再 `Tr()`。
    - `g` 按 `language/` 下 `*.json` 文件名排序循环切换，写入 `preference.json` 的 `language`（文件名，如 `"CN"`）；v1.3.0 的 `"zh-CN"` 自动对应 `CN`。
    - 按钮、标签等在构造时生成文字，所以切换语言后 `App` 退出事件循环，`RunApp` 重新构造整个界面；`AppState`（数据、选中日期）保留。
    - 语言文件缺失或格式错误时使用英文并在状态栏提示。农历名称、节气、节假日名称不翻译。
    - 单元测试检查 `EN.json` 的 key 与 value 相同、`CN.json` 覆盖全部 key 且占位符一致。
    - 英文比中文长：对话框加宽、表单标签宽度改为 16、任务总览的状态和星期列加宽。
    - README 和设计文档各有中英两版：`README.md` / `README_CN.md`，`docs/design.md` / `docs/design_CN.md`。
17. **v1.5.0 农历开关**：`u` 切换 `preference.json` 中的 `lunar`（默认 true）。
    关闭时月历格子第二行只显示节假日名（不显示农历日期、农历节日和节气），侧边栏原来农历日期和节日/节气两行的位置显示标语（见第 18 条）。
18. **v1.5.0 标语**：状态栏没有消息时显示标语（`preference.json` 的 `slogan`，默认“Look Forward!”，用户自己写的文字，不翻译）。启动时清除“已刷新”，让状态栏显示标语。`e` 打开 `SloganDialog` 修改，留空恢复默认。
