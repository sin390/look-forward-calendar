# 日历程序设计文档

基于 FTXUI 的终端日历：月视图 + 日程管理（瞬间型事件 / 长期任务）+ 农历 + 中日节假日。

## 1. 技术栈

| 项目 | 选择 |
|---|---|
| 语言 | C++20（日期计算用 `<chrono>`） |
| UI | FTXUI v7.0.3 |
| JSON | nlohmann/json（header-only，FetchContent 引入） |
| 构建 | CMake + Ninja，GCC 15.1（MinGW），静态链接 |
| 平台 | 仅 Windows，不考虑跨平台 |

## 2. 数据目录

根目录为 **exe 所在目录**下的 `data/`（不依赖启动时的工作目录）。

```
data/
  general/<年>/<月>.json        当月每天的属性及瞬间型事件，例：general/2026/11.json
  task/<创建日期>_<短id>.json   每个长期任务一个文件（操作日志），例：task/20261102_a3f9.json
  holidays/<国家>_<年>.json     导入的节假日，例：holidays/CN_2027.json
```

## 3. 数据模型

### 3.1 Day（每天一个对象）

`general/2026/11.json`：以日期为键，没有内容的日期不写入。

```json
{
  "2026-11-02": {
    "events": [
      { "title": "组会", "start": "14:00", "end": "15:30", "note": "" }
    ]
  }
}
```

- 瞬间型事件直接保存在 Day 上。
- 事件的增删改都是直接改写当月文件。

### 3.2 Task（长期任务，一个任务一个文件）

文件里保存的是**操作日志**，任务的当前状态和每天的工作量都由重放日志计算得到。

```json
{
  "id": "a3f9",
  "name": "毕业论文",
  "log": [
    { "at": "2026-11-02T22:10", "op": "create",
      "hours_total": "40:00", "due": "2026-12-20",
      "weekdays": [1, 2, 3, 4, 5], "skip_holiday": true, "country": "CN" },
    { "at": "2026-11-03T21:00", "op": "progress", "date": "2026-11-03", "minutes": 150 },
    { "at": "2026-11-10T09:00", "op": "modify", "fields": { "due": "2027-01-10" } },
    { "at": "2026-11-15T20:00", "op": "pause" },
    { "at": "2026-11-18T20:00", "op": "resume" },
    { "at": "2026-12-01T18:00", "op": "complete" }
  ]
}
```

| op | 含义 | 字段 |
|---|---|---|
| `create` | 创建 | 预定总时长、截止日期、每周工作日（1=周一…7=周日）、是否跳过节假日、节假日国家 |
| `progress` | 录入某天实际工作量 | `date`、`minutes`（同一天再次录入时覆盖，**待确认，见 §9**） |
| `modify` | 修改属性 | `fields`：总时长 / 截止日期 / 工作日 / 名称等 |
| `pause` / `resume` | 暂停 / 恢复 | 暂停后截止日期不变 |
| `complete` | 提前（或按期）完成 | |
| `abort` | 中止 | |

- 短 id：创建时随机生成 4 位十六进制，作为属性保存；如果和已有任务重复就重新生成。
- 文件名：`<创建日期>_<短id>.json`，任务名只保存在文件内容里。

### 3.3 任务状态机

```
           pause            complete / abort
 进行中 ─────────▶ 暂停 ─────────────────▶ 已结束
   ▲ ◀─────────── │
   │    resume    │
   └─ 超期未完成 ─┘（自动进入暂停，标红）
```

### 3.4 每日工作量计算

对某个任务和日期 D（今天及以后）：

```
R = 总时长 − 实际录入工时之和（今天之前的）
N = 今天 到 截止日期 之间的工作日数（包括今天）
工作日 = 星期属于 weekdays，且（skip_holiday 为假，或该日不是 country 国的放假日）
每天分配量 = ceil(R / N)，向上取整到 10 分钟
```

- 创建当天算一天。
- 没有录入的日子按 0 分钟计，后续几天的量会自动增加。
- 暂停期间不分配工作量，截止日期不变，恢复后每天的量相应增加。
- 已完成、已中止的任务不再分配。
- 今天超过截止日期但 R > 0：任务标红，进入暂停状态。
- **过去的日期**：显示当天实际录入的工时；也可以把日志重放到那一天，显示当时的计划量。
- **刷新按钮**：当天修改了任务属性后，重新读取文件、重新计算后续安排（也用于跨过零点后更新“今天”）。

## 4. 农历

- 内置 1900–2100 年的农历压缩数据表（每年一个整数，编码闰月和大小月），不联网。
- 能算出：农历日期、干支、生肖、农历节日（春节、元宵、端午、七夕、中秋、重阳、除夕）、二十四节气（含清明、冬至）。

## 5. 节假日

### 5.1 统一格式 `holidays/<国家>_<年>.json`

```json
{
  "country": "CN",
  "year": 2027,
  "days": [
    { "date": "2027-02-06", "name": "春节", "off": true },
    { "date": "2027-02-14", "name": "春节调休补班", "off": false }
  ]
}
```

- `off: true` 表示放假日；`off: false` 表示补班日（只有中国有）。
- 只列出特殊日期，没列出的日期按普通工作日或周末处理。

### 5.2 导入流程

1. 在程序里按快捷键，选择国家和年份，弹窗显示提示词，并自动复制到剪贴板。
2. 用户把提示词发给任意 AI，把返回的 JSON 保存成文件。
3. 在程序里输入文件路径，程序校验格式（字段、日期是否合法、年份和国家是否一致）。
4. 校验通过后写入 `holidays/<国家>_<年>.json`，同一国家同一年的旧数据整体覆盖。

### 5.3 提示词模板（程序内置，`{COUNTRY}` / `{COUNTRY_NAME}` / `{YEAR}` 会被替换）

```
请列出{COUNTRY_NAME}{YEAR}年全年的法定节假日安排，严格按照下面的 JSON 格式输出，
不要输出 JSON 以外的任何文字，也不要使用 Markdown 代码块。

{
  "country": "{COUNTRY}",
  "year": {YEAR},
  "days": [
    { "date": "YYYY-MM-DD", "name": "节日名称", "off": true }
  ]
}

规则：
1. 每个日期单独一条，连续放假的每一天都要列出。
2. 放假日（含周末因节日顺延的补休/振替休日）"off" 为 true。
3. 因调休需要上班的周末（补班日）也要列出，"off" 为 false，name 写“XX调休补班”。
4. name 使用该国语言的通用名称。
5. 只列出 {YEAR} 年内的日期，按日期升序排列。
6. 依据该国政府官方公布的安排；如果官方尚未公布，请在 name 后加“(预测)”。
```

## 6. 界面（月视图）

```
┌ 2026 年 11 月 ──────────────────────────────────┬ 11月2日 周一 ─────────┐
│  一     二     三     四     五     六     日   │ 农历 十月初二          │
│ ┌────┐                                          │                        │
│ │ 2  │  公历日 / 农历或节日、节气                │ 【事件】               │
│ │初二│                                          │  14:00-15:30 组会      │
│ │●2  │  瞬间型事件数                            │                        │
│ │▶3h │  当天任务总工时（超期任务标红）           │ 【任务】               │
│ └────┘                                          │  毕业论文  计划 2:00   │
│                                                 │            实际 [____] │
│                                                 │  [暂停][完成][修改]    │
├─────────────────────────────────────────────────┴────────────────────────┤
│ ←↑↓→ 移动  PgUp/PgDn 翻月  a 新建事件  t 新建任务  r 刷新  h 节假日导入 │
└──────────────────────────────────────────────────────────────────────────┘
```

- 每周从周一开始。
- 放假日和补班日用不同颜色标出；格子里显示任务计划工作的星期。
- 侧边面板：当天的事件列表；各任务当天的计划量、实际工作量输入框，以及状态按钮（暂停 / 恢复 / 完成 / 中止 / 修改），任何日期都可以操作。

## 7. 模块划分

```
src/
  core/
    date.h/.cpp        日期工具（基于 std::chrono::year_month_day）
    lunar.h/.cpp       农历、节气、农历节日
    holiday.h/.cpp     节假日表的加载、查询、校验、导入
  model/
    day.h/.cpp         Day / Event 及 JSON 转换
    task.h/.cpp        Task 日志、状态重放、每日工作量计算
  store/
    paths.h/.cpp       data 目录定位（exe 所在目录）
    repository.h/.cpp  读写 general/ task/ holidays/
  ui/
    month_view.*       月历网格
    side_panel.*       侧边面板
    dialogs.*          新建/编辑事件、任务，导入节假日
    app.*              组装、快捷键、刷新
  main.cpp
tests/                 core / model 的单元测试（doctest）
```

`core` 和 `model` 不依赖 FTXUI，可以单独测试。

## 8. 开发步骤

1. **基础**：日期工具、data 路径、nlohmann/json 引入、单元测试框架
2. **农历**：数据表、农历日期、节日、节气，并加测试
3. **节假日**：统一格式、校验、导入、提示词与剪贴板
4. **Day / Event**：模型、按月读写
5. **Task**：日志、状态重放、工作量计算（重点测试）
6. **UI**：月视图 → 侧边面板 → 各对话框 → 快捷键与刷新
7. 收尾：异常处理（文件损坏、缺少节假日数据时的提示等）

## 9. 待确认

1. **补班日**：任务的工作日只选了周一到周五时，中国的补班周六要不要分配工作？
   建议：`skip_holiday` 为真时，补班日视为工作日（按周一到周五处理）。
2. **今天的计划量是否固定**：如果今天录入了 1h，按公式实时计算的话今天的计划量会马上变小，看起来很奇怪。
   建议：今天的计划量只用**今天之前**的工时计算（即 §3.4 的写法），录入今天的工时不改变今天的目标，只影响明天以后。
3. **录入工时的方式**：同一天多次录入是**覆盖**（设定当天的总量）还是**累加**？能不能补录过去的日期？
   建议：覆盖，并且允许补录。
4. **超期自动暂停**：是在日志里写入一条 `pause` 记录，还是只作为计算出来的状态（不写日志）？
   建议：只作为计算状态，用户延长截止日期后自动恢复。
5. **节假日数据缺失**：任务跨到还没导入节假日的年份时，是否在界面上给出提醒？
